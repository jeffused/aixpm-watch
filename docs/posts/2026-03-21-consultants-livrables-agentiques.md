# L'IA autour du livrable, pas dans le livrable

Un fil de 88 commentaires sur r/consulting fait converger les praticiens sur un point précis : les agents IA accélèrent le travail qui précède le slide, rarement le slide lui-même. La question initiale — « à quoi servent vraiment Claude Code, Codex ou les workflows agentiques quand on ne code pas ? » — fait remonter une quinzaine de témoignages détaillés, et un consensus émerge.

Le pattern dominant traite l'IA comme un analyste junior structurant. Plusieurs consultants décrivent la même chaîne : déverser des notes client ou un verbatim d'atelier, faire structurer hypothèses et risques, générer un strawman, puis stress-tester les angles morts avant un comité de pilotage. L'un d'eux résume l'idée centrale : « stop using them for one-shot answers, start using them as a deterministic environment for repetitive workflows ». Un autre liste explicitement les usages : « structuring messy client notes into issue trees », « iterating on slide storylines (outline → stress test → tighten logic → refine language) », « generating edge-case scenarios before a steering committee ».

Le signal contraire est tout aussi net sur la mise en page directe. Un consultant ayant tenté Claude Cowork pour produire des slides parle de « nightmare » et signale que l'outil a effacé du contenu existant malgré une consigne explicite de ne toucher qu'à certaines diapositives. Côté gouvernance, un participant note que son cabinet n'autorise que ChatGPT — confirmation que la question du périmètre d'outils reste verrouillée à la DSI dans bon nombre de structures.
