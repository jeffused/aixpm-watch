# Transcription IA en reunion : cinq workflows de chefs de projet, un seul refrain

Sur r/projectmanagers, une question ouverte — « est-ce que vous vous reposez vraiment sur la transcription IA pour vos notes de reunion ? » — fait remonter cinq pratiques distinctes, qui convergent toutes vers le meme principe : la machine capte, le PM controle.

Le workflow le plus etoffe vient d'un chef de projet TDAH inattentif. Il injecte la transcription avec l'ordre du jour, le pack du comite de pilotage et le tableau RAID, puis demande au LLM « de produire les minutes et les actions sur la base des informations nouvelles uniquement », ou de « comparer la discussion au RAID et identifier les ecarts ». Un autre combine Zoom et Fathom pour la capture, puis bascule le transcript dans Claude Code avec un document modele : la sortie ressort dans le style impose, prete pour le reporting. Un troisieme cite Granola.ai pour sa couche LLM transversale — « retrouve toutes les conversations ou ce point a ete evoque, sors les obstacles de tous mes appels » — qui ouvre la requete inter-reunions. Un quatrieme s'appuie sur Notion AI couple a un systeme PM/Programme dans le meme outil. Un cinquieme decrit une integration Zoom proprietaire epaulee par un chatbot pour creuser les details que le resume comprime. Copilot apparait en arriere-plan, salue pour les actions mais epingle pour son zele : « si quelqu'un suggere a peine une bonne idee, il en fait une action ».

Le signal commun n'est pas le choix d'outil, c'est le statut accorde a la sortie : aucun praticien ne traite la transcription comme livrable. « Je les traite comme un filet de securite, pas comme une source de verite », resume l'un d'eux. La fonctionnalite vraiment differenciante — au-dela du resume mono-reunion — n'est pas la transcription elle-meme, mais la couche d'extraction structuree posee par-dessus : actions, decisions, ecarts RAID, requete trans-comites. Le transcript brut, lui, reste un brouillon.
