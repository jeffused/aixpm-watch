# Claude pour les decks : un accelerateur d'idees, pas un generateur de slides

Soixante-huit reponses sur r/consulting convergent vers un meme constat : Claude est utile pour penser un deck, pas pour le fabriquer cle en main. Le commentaire le mieux note resume le consensus : « It's never going to give you a finished deck, but it's getting closer to the desired end result. » Plusieurs praticiens revendiquent un score « 8 sur le contenu, 6-7 sur le design ».

Cinq workflows ressortent. Le plus partage : alimenter Claude en narration structuree, lui demander des titres d'action style MBB et des takeaways, puis recopier le texte dans PowerPoint et formater soi-meme. La variante Cowork ou Claude code consiste a fournir la charte et un deck de reference, et a iterer six a dix fois sur la skill PowerPoint ; un consultant decrit douze decks finalises sans retouche humaine en quelques semaines. Pour les decks repetitifs, on pointe Claude vers une source de donnees et l'on batche cinquante slides d'initiatives ou de roadmap. Les autres options : exporter en HTML avant PDF, ou passer le storyline a Gamma, PlusAI ou NotebookLM pour le rendu visuel.

Le cadrage qui revient le plus souvent est aussi le plus operant : « use it before PowerPoint and around PowerPoint, not instead of PowerPoint. » La valeur se loge dans la pensee narrative humaine — storyline, titres d'action, synthese de notes — et l'IA accelere la mise en mots, pas la mise en forme du livrable.
