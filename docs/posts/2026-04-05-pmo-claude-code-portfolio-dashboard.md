# Le PMO comme cas limite : agreger un portefeuille avec Claude Code et MCP

La douleur classique du PMO interne, c'est l'eparpillement : Smartsheet pour les plannings, Monday pour les actions, Sheets pour les budgets, Slides pour la direction, ClickUp ou Jira pour le delivery. Aucune vue unifiee, pas de memoire projet, et la moitie du travail consiste a recopier d'un outil vers l'autre. Un fil de 40 commentaires sur r/projectmanagement, ouvert par un PMO qui demande « ce que vous utilisez l'IA *pour de vrai* aujourd'hui », fait remonter un cas qui se detache.

Une PM raconte avoir branche Claude Code sur ses sources internes : conversion automatique de threads Slack en entrees RAID, organisation d'un shared drive de 500 documents reconstitue a partir de Slack et Drive, et surtout un portfolio dashboard unifie qui agrege Sheets, Slides, Smartsheet et Monday, publie sur GitHub Pages. C'est l'archetype du « PMO augmente » : pas un outil de plus, mais une couche qui lit les outils existants. Un autre PM cible plus modestement la generation de project plans dans ClickUp via Claude + MCP ; un profil senior chiffre son gain sur Copilot Workspaces — « 4 a 6 heures par semaine » recuperees sur la phase de degrossissage des documents portes a 80-90 %.

Le contre-signal a retenir vient de la praticienne du dashboard elle-meme : « *But is it making the projects actually run better? Eh, I would not say that, actually.* » Le PMO devient le terrain ou les workflows IA sortent du prototype parce que l'eparpillement y coute le plus — mais le gain reste, pour l'instant, du cote de la productivite individuelle, pas de la performance projet.
